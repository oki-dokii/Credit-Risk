# Reproduce the validation work

## Environment and demonstration

Use Python 3.10–3.12 (tested on 3.12). From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-validation.txt
python validate.py
python -m unittest discover -s tests -v
```

The validation dependency list omits interactive notebooks and SHAP because neither is needed
for these experiments. The legacy training command uses requirements.txt for its SHAP report.
The synthetic generator uses explicit distributional assumptions and a latent logistic outcome
mechanism. It does not download, approximate or purport to reproduce the Kaggle dataset.
Run metadata records package versions, config/data hashes, sample count and seeds.
requirements-validation-lock.txt records the exact packages used for the committed demo.

Default outputs use a 60/20/20 stratified random split. All OOT labels mean **simulated OOT proxy**.
The run exports all three splits for both models, Brier/log loss, mean PD versus event rate,
joint calibration intercept/slope, reliability bands, score PSI and perturbation results.
Raw rows, row-level predictions, bridge design and local fitted bundles are regenerated by the
command and excluded from Git. Small summary tables and the memo are committed for review.
The saved validation bundle holds the frozen preprocessor and both models for local inspection.

A real-data run is explicit and must use a separate output directory:

```bash
python validate.py --data /absolute/path/cs-training.csv --output outputs/real_validation
```

The real-data path still uses random splits: supplying real data does not make the proxy temporal.
Provide numeric features named in src/data_utils.py, and a binary SeriousDlqin2yrs target.
Extra columns such as CSV row indices are discarded; input row order defines exported row IDs.
Do not commit sensitive applicant data or predictions to a public repository.

## What the demonstrations establish

The independent metric module recomputes AUC, Gini, KS and probability calibration from
predictions rather than relying on the imported results. Independent refers to computation,
not a separate validation organization or a second research dataset.

Monitoring compares a frozen model against the original proxy cohort, then creates a feature-shifted
batch with income at 35%, utilization at 1.5, and four additional 90-day delinquencies.
Its original labels are fixed, so resulting performance is a controlled software sensitivity test.
A separate artificial 1-y label inversion guarantees a strong performance degradation signal
when the reference model has positive Gini, exercising the performance alarm without claiming
that such an outcome mechanism is realistic. The demo fails if its required alarms do not fire.

Stress tests report the approval share, whole-portfolio expected default rate, approved-portfolio
expected default rate, and a fixed-label observed approved-portfolio rate. They have different
meanings: expected rates come from model PD; fixed-label rates capture selection under a new policy.
No experiment identifies a causal effect or a new realized portfolio default rate.

## SAS execution and reconciliation

SAS is not needed to generate the bridge; it is needed to establish cross-platform agreement.

1. Run validate.py to export outputs/validation/reconciliation/design.csv, feature_mapping.csv,
   python_coefficients.csv, python_predictions.csv, python_metrics.csv, manifest.json and reconcile.sas.
2. Copy that directory to a SAS environment. Set bridge_dir in reconcile.sas to its absolute location.
3. Run the generated program. Check the SAS log for convergence, quasi/complete separation,
   dropped rows or changes to the event convention. Save that log as validation evidence.
4. Bring sas_predictions.csv and sas_coefficients.csv back without rounding or editing their values.
5. Run the comparator:

```bash
python reconcile.py --directory outputs/validation/reconciliation \
  --sas-predictions /absolute/path/sas_predictions.csv \
  --sas-coefficients /absolute/path/sas_coefficients.csv
```

The SAS program reads the same preprocessed and WOE-encoded design matrix. It does not refit bins,
imputation or feature selection. SAS terms w001 etc. map to original features in feature_mapping.csv.
The bridge is a separately fitted **unpenalized** logistic model; the champion retains its L2 penalty.
Both bridge fits include an intercept, model target=1, and use no weights or class adjustments.
Rows and split membership must match one-to-one. Returned design values must agree to 1e-12;
coefficient absolute tolerance is 1e-4, PD tolerance 1e-5, and per-split Gini tolerance 1e-6.
A failed comparison exits nonzero. A numerical pass still requires the SAS log review.

When SAS results are unavailable, status remains PENDING_SAS_EXECUTION. Python fixture exports
used in unit tests are intentionally not stored as SAS evidence or fed into the demonstration memo.
